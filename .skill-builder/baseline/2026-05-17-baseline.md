## Methodology

Each Q sent to the model with this minimal system prompt:

> You are a DOT compliance reference. Answer each question concisely. When you cite a regulation, give the full 49 CFR citation. Do not invent citations. If unsure, say so.

Grading is automatic + conservative:
- **Pass** if answer contains the expected CFR section (base section match, ignoring subsection chars).
- **Fail** if answer omits the citation, OR contains a numeric pattern from the question's `common_hallucinations` list.
- Strict citation check, not semantic — the model can technically know the answer but cite a wrong section and fail. That's intentional: skills need exact citations.

## What this number tells us

With **85% baseline accuracy**, the assessment is:
- **80-94% (we're here)**: skill-builder agent NEEDS retrieval grounding (eCFR API round-trip) to lock down citations before any output is committed. The model knows most of the regs but mis-cites in the edge cases.

## Decision: how the skill-builder must be built

1. **Retrieval-grounded generation:** every skill draft must `GET` the cited section via `ecfr.federalregister.gov/api/versioner/v1/full/...` and verify the section exists + the claimed regulation text appears in it.
2. **Post-generation verification step:** the agent re-asks itself "does the actual eCFR text support this skill's claim?" before opening a PR.
3. **Per-section eval gate:** any skill in a failing category from this baseline must achieve 100% on that category's eval Q's before PR can be merged.
4. **Human merge gate:** all skill PRs land on `agent/skill-builder/*` branches, never directly to main.
